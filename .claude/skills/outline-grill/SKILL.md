# 大纲盘问（outline-grill）

机制借鉴 grill-me 的 design tree / frontier / 推荐答案（MIT 项目，本文件为自写实现，不复制其文本）。
区别：**每个问题必须带转写证据，且先跑确定性检查。**

## 前置

1. 定位工作区：`work/<slug>/`（用 `python scripts/status.py` 确认）。
2. 跑确定性检查（M2 起可用）：
   ```bash
   python scripts/check_outline.py work/<slug>/outline.md --slug <slug>
   ```
   失败项直接作为第一轮问题的证据；脚本不存在时，手工核对时间范围与覆盖率。
3. 读 `outline.md` 与 `transcript.txt`（按时间分块，不要一次读全文）。

## 建树

把"这份大纲能否支撑一节真实的课"拆成决策树，节点示例：

- 章节数是否等于视频真实结构？（有没有把两个主题硬塞进一章）
- 每个章节的时间范围是否首尾相接、无重叠、无大段遗漏？
- 哪些小节该合并（同一论点被拆散）？哪些该拆（一章跨了多个主题）？
- 标为"低置信度"的段落，用户能否确认其内容？
- `[图]`/`[公式]`/`[代码]` 标记是否覆盖了对应帧与转写？
- 章节标题是否"结论化"（读者看目录就知道学到了什么）？

## 每轮

1. 只问 **frontier**：所有前置决策已确定的节点。
2. 问题编号列出，每个问题给：
   - 问题本身
   - **推荐答案**（措辞让"同意"就是接受推荐）
   - **证据**：转写时间戳 + 原文摘录，或帧路径
3. 事实自己查（转写、帧、脚本输出），**只把决策交给用户**。
4. 用户回答后重算 frontier，进入下一轮。

## 结束

- frontier 为空时，请用户明确确认"大纲已定稿"。
- 把每轮决策写入 `work/<slug>/outline-decisions.md`（问题 / 选择 / 理由 / 证据）。
- 未确认前不得进入 S4。

## 禁止

- 不要一次抛出 20 个问题；一轮 3–6 个，按依赖排序。
- 不要问能用脚本回答的事实（时长、覆盖率、时间戳单调性）。
- 不要在用户未确认时自行"替用户决定"并继续写笔记。
