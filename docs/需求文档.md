# 视频 → Markdown 笔记 → HTML 课件 自动化流水线

> 需求文档 v0.1 ｜ 2026-11-11 ｜ 状态：草案（待确认项见 §14）

---

## 0. 文档目的

把「我有一堆录好的课/讲座视频」变成「可复习的文字笔记 + 可直接讲的网页课件」这件事，
从一次性手工劳动，固化成一条**在 Claude Code 里分步执行、每步可人工干预**的流水线。

本文档定义：做什么、不做什么、每一步的输入输出与验收标准、产物规范、里程碑与风险。

---

## 1. 背景与问题

现状：本地有一批视频（课程、讲座、自己的录屏）。完整看一遍耗时；看完记不住；
想做二次讲授（课件）又要重新整理一遍。

三个痛点：

1. **信息密度低**：1 小时视频的有效信息，写下来通常只有 3–5 页笔记。
2. **检索困难**：想起某个点，却不知道在第几分钟。
3. **复用成本高**：笔记 → 课件的转换是纯体力活，排版、提炼、配图都要重做。

目标不是"让 AI 替我看视频"，而是让 AI 承担**转写、提炼、成稿、排版**四件事，
人只保留**判断**（大纲对不对、重点选得准不准、课件讲得顺不顺）。

---

## 2. 目标与非目标

### 2.1 核心目标

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 任意本地视频 → 一份可信、可检索、带时间戳的 MD 笔记 | 每节内容可回溯到原视频时间点 |
| G2 | 该笔记 → 一份 16:9、可离线打开、可直接照讲的 HTML 课件 | 双击 `index.html` 即可放映，无需联网 |
| G3 | 全流程分步、可中断、可重跑，单步失败不污染其他步骤 | 改了大纲只需重跑后续步骤 |
| G4 | 不引入额外云服务/API Key，转写与抽帧全部本地完成 | 断网环境下除 Claude 外全流程可跑 |

### 2.2 成功指标（v1 验收）

- 60 分钟中文视频，从运行到出稿 ≤ 30 分钟（其中转写 ≤ 12 分钟）。
- 笔记覆盖原视频内容 ≥ 95%（按章节时长核对），关键结论无事实性错误。
- 课件页数 = 有效内容章节数 × 1.5~3，每页信息量符合 §9.3 的密度规则。
- 笔记与课件的术语、数据、结论**完全一致**（同一份大纲驱动）。

### 2.3 明确不做（Non-Goals）

- ❌ 视频下载 / 在线平台抓取（如 YouTube、B 站）——v1 只处理本地文件。
- ❌ 视频剪辑、字幕烧录、配音、自动生成视频。
- ❌ 多语言互译（v1 只做原语言笔记，中文视频可保留英文术语）。
- ❌ 实时/直播处理。
- ❌ 追求"取代人工写课件"——定位是**初稿 + 排版**，人做终审。
- ❌ 通用视频理解（如影视解说、动作分析）——只面向**以讲解为主的视频**。

## 3. 关键事实与架构约束

这一节决定整个方案长什么样，必须先讲清楚：

1. **Claude 无法直接"观看"视频。** 视频对模型而言是"音频流 + 图像序列"，而：
   - **音频**不能直接输入 → 必须先用 ASR 转成带时间戳的文本；
   - **画面**只能以静态图片读取 → 按场景变化**抽帧**成 JPG，再让 Claude 逐张看。
   所以"AI 观看视频"落地为 **转写文本 + 关键帧图片** 两条并行输入。这是本方案的基石。
2. **本机环境已就绪**：ffmpeg 7.1 / Python 3.10.9 / Node 24 / RTX 4060 Laptop 8GB。
   8GB 显存足够 `faster-whisper large-v3` 以 `int8_float16` 运行；
   但 Windows 需额外安装 CUDA 12 运行库（cuBLAS/cuDNN），缺失时自动回退 CPU。
3. **纯本地、无额外 Key**：ASR 用本地 faster-whisper，抽帧用 ffmpeg，成稿用 Claude Code 自身。
4. **交付形态是 Claude Code 工作流**（不建后端、不做 Web 应用）：
   用 `.claude/` 下的 skill + 斜杠命令编排，Python 脚本只承担确定性计算（音视频处理）。
5. **Windows 环境**：脚本须兼容中文路径、空格路径、CRLF；统一用 `pathlib`，不拼接字符串路径。

## 4. 用户与使用场景

**主用户**：需要反复消化视频、并对外讲授的人（教师/讲师/技术分享者）。
**使用频次**：按批处理，一次 1–N 个视频。

典型场景：

- **S-A 精读**：拿到一节 90 分钟的大课，先出笔记速读，只回看被标记为"关键/存疑"的片段。
- **S-B 备课**：已有笔记，生成 20–30 页课件，改排后直接讲课。
- **S-C 复习**：直接打开笔记，点时间戳跳回原视频对应位置。
- **S-D 归档**：把一批视频转成文本库，便于以后全文搜索。

## 5. 总体架构

```
                    ┌──────────── 本地，脚本完成 ────────────┐   ┌──── Claude Code 完成 ────┐
 videos/xxx.mp4 ──► │ S0 预处理  S1 转写  S2 抽帧            │──►│ S3 大纲  S4 笔记  S5 课件 │──► output/
                    └───────────────────────────────────────┘   └──────────────────────────┘
                              │                                            │
                              ▼                                            ▼
                     audio.wav / transcript.*                        notes.md / slides/
                     frames/*.jpg + index.json                       （每步可人工修改后再继续）
```

六个阶段，每阶段有独立产物落盘，可单步重跑：

| 阶段 | 执行者 | 产物 | 主要工具 |
|---|---|---|---|
| S0 预处理 | 脚本 | `meta.json`、`audio.wav` | ffprobe / ffmpeg |
| S1 转写 | 脚本 | `transcript.json/srt/txt` | faster-whisper |
| S2 抽帧 | 脚本 | `frames/*.jpg`、`index.json` | ffmpeg scene detect |
| S3 大纲 | Claude | `outline.md` | Read 文本 + 图 |
| S4 笔记 | Claude | `notes.md` | — |
| S5 课件 | Claude | `slides/index.html` | 渲染 + 截图自检 |

> 设计原则：**脚本只做确定性的事，Claude 只做判断性的事。** 任何"能算出来的"都不交给模型。

## 6. 目录与产物规范

```
video-md-ppt/
├─ videos/                       # 原始视频（不入 git）
├─ work/<slug>/                  # 中间产物，可删可重建
│  ├─ meta.json                  # 视频元信息 + 各阶段状态
│  ├─ audio/audio.wav            # 16kHz mono 16bit，转写用
│  ├─ transcript/
│  │  ├─ transcript.json         # 结构化分段（含词级时间戳）
│  │  ├─ transcript.srt
│  │  └─ transcript.txt          # 带 [mm:ss] 前缀的纯文本，喂给 Claude 用
│  ├─ frames/
│  │  ├─ 000000123.jpg           # 文件名 = 毫秒时间戳
│  │  └─ index.json              # 帧 ↔ 时间点 ↔ 触发原因（scene/interval）
│  ├─ outline.md                 # S3 产物
│  ├─ enrichment.md              # S4.5 知识深挖卡（推理层）
│  ├─ fact-check.md              # S4.6 内容核查表
│  ├─ notes.md                   # S4 产物（工作副本）
│  └─ notes.assets/              # 笔记引用的图（从 frames 精选）
├─ output/<slug>/                # 交付物
│  ├─ notes.md
│  ├─ notes.html                 # 可选：博客风格渲染版
│  ├─ slides/
│  │  ├─ index.html              # Marp 单文件 HTML
│  │  ├─ index.pdf               # 可选，字体已嵌入
│  │  ├─ theme.css               # 中文排版主题
│  │  └─ assets/                 # 图片等本地资源
│  └─ report.md                  # 生成报告：耗时、抽检、待人工确认项
├─ scripts/                      # 确定性脚本
└─ .claude/
   ├─ skills/video-notes/SKILL.md
   └─ commands/{transcribe.md, notes.md, slides.md}
```

`slug` 规则：`<视频文件名>_<内容hash前8位>`，避免同名覆盖、便于增量重跑。
`meta.json` 记录每阶段的 `status / 参数 / 耗时 / 产物校验和`，用于判断能否跳过。

## 7. 分阶段需求

### S0 预处理

**目标**：把任意容器格式规整成后续步骤能吃的标准输入。

- 用 `ffprobe` 读取时长、分辨率、帧率、音轨数、语言标签，写入 `meta.json`。
- 抽取音频：`ffmpeg -vn -ac 1 -ar 16000 -sample_fmt s16 audio.wav`。
- 无音轨 / 音轨静音时**直接报错并说明**，不进入后续阶段。
- 视频超过 2 小时时提示分段，但仍支持处理。

**验收**：任意 mp4/mkv/mov/avi/flv/webm 均能生成合法 wav；错误信息可操作。

### S1 转写（"听"）

- `faster-whisper large-v3`，CUDA + `int8_float16`，VAD 过滤静音。
- 开启 `word_timestamps=True`、`vad_filter=True`，`language` 自动检测（中文优先，可在配置里强制）。
- 输出三份：结构化 JSON（段落 = 语义停顿）、SRT、带 `[mm:ss]` 的纯文本。
- 说话人分离为**可选增强**（pyannote），v1 不阻塞主流程。
- 术语纠正：允许用户提供 `glossary.txt`，用 `hotwords` / 后处理替换，减少专有名词错字。
- 转写完成后打印前 200 字与预计全文长度，便于人工快速判断语言/轨道是否选对。

**验收**：60 分钟中文视频 ≤ 12 分钟完成；人工抽检 5 段，语义可读、时间戳误差 ≤ 2 秒。

### S2 抽帧（"看"）

- **策略**：场景变化检测（`select='gt(scene,0.3)'`）为主，固定间隔（每 30 秒）兜底；
  幻灯片型画面变化平缓，另加"画面文字占比突增"启发式（v1 可只做 scene + interval）。
- **预算**：默认每 10 分钟 ≤ 12 帧，单视频上限 80 帧；超限时按"场景分差"降采样。
- 输出 JPG 宽 1280，质量 3；`index.json` 记录 `{path, t_ms, reason, diff_score}`。
- 后续按需只把**与当前章节相邻**的帧喂给 Claude，避免一次性塞满上下文。

**验收**：抽帧覆盖所有"换页/换板书/出现图表"的时刻（人工核对 3 处）；单帧 ≤ 200KB。

### S3 大纲（第一个判断点）

- Claude 读 `transcript.txt`（超长视频按 20–30 分钟重叠切块，逐块出小节再合并）。
- 产出 `outline.md`：一级章节 + 二级要点 + 每节时间范围 + 标注 `[图]`/`[公式]`/`[代码]` 的位置。
- **必须**标注"低置信度段落"（转写含糊、语义跳跃），供人复核。
- 此步是人工干预的主入口：改完大纲再继续，后续所有产物都从它派生。

**验收**：章节数与视频实际结构一致；每章有起止时间；无空章节、无章节重叠。

### S4 笔记

- 以 `outline.md` 为骨架，逐节写正文（规范见 §8）。
- 图：只从 `frames/` 里选**信息量最高**的帧，复制到 `notes.assets/`，配图注 + 时间戳。
- 笔记完成后做一次**自检**：时间戳单调递增、覆盖全片、术语表与正文一致、无"根据视频内容"之类空话。

**验收**：见 §8.4 质量清单。

### S4.5 知识深挖（推理层）

- 以 `outline.md`、`notes.md` 与抽帧为输入，列出全片 15–25 个核心知识点。
- 每个知识点写一张卡到 `work/<slug>/enrichment.md`，字段：对应视频 / 一句话 / 原理 / 例 / 易错 / 迁移 / 来源。
- **来源三级**：
  - `〔视频〕` 讲者原话或原例，必须带 `[mm:ss]`；
  - `〔推演〕` 从视频规则推导出的解释，可无新时间戳，但必须能追到原规则；
  - `〔扩展〕` 视频外补充的标准知识，不得写成"老师说的"。
- 讲者表述是教学简化时，另写"校正卡"，课件标"讲者的简化"，不直接判定讲者错。
- 学科外部知识必须可核对；没有把握的词源、统计、推荐不做。
- 脚本：`python scripts/check_enrichment.py work/<slug>/enrichment.md`，至少 12 张卡，
  〔视频〕/〔推演〕/〔扩展〕各 ≥4 张，缺字段或来源不分级即 FAIL。

**验收**：`check_enrichment.py` 为 `OVERALL PASS`。

### S4.6 内容核查

- **写查分离**：由不继承写作上下文的独立子代理核查；写作者不得自己判“没问题”。
- 核查对象：`transcript.txt`、`notes.md`、`enrichment.md`、`slides.md`。
- 核查项：事实错误、过度概括、争议规则、错误归因、内部矛盾、英文例句自然度。
- 产出 `work/<slug>/fact-check.md`，表头：
  `| ID | 位置 | 主张 | 类型 | 判定 | 说明 | 处理 |`
  - 判定：`OK` / `WEAK` / `ERROR` / `CONTESTED`
  - 类型：视频原意 / 语法规则 / 词源 / 例句 / 术语
- 处理规则：
  - `ERROR` 必须改，不能留待处理；
  - `WEAK` 收紧措辞或加限定；
  - `CONTESTED` 必须在课件可见处标“考试约定/有争议”，不能只写备注；
  - 视频本身的错误/简化，课件标“讲者的简化/口误”，不照抄。
- 脚本：`python scripts/check_factcheck.py work/<slug>/fact-check.md --enrichment ... --slides ...`，
  至少 20 行、每张 E 卡被查、每个扩展页被查、ERROR 全部有处理。

**验收**：`check_factcheck.py` 为 `OVERALL PASS`，且课件已按核查结果重渲染。

### S5 课件

- 由笔记 + `enrichment.md` 生成 `slide-plan.md`（每页：标题 / 3–5 个要点 / 配图 / 讲者备注 / 时长）。
  计划可人工调整，再渲染 HTML。
- 每个核心知识点至少一页深挖（原理、对比、迁移或自测），整场不能只有原视频结论。
- 每页角标标来源；〔扩展〕页不得出现"视频里说"。
- 生成 `slides/index.html` + `assets/`，**完全离线**。
- 用浏览器自动截图（1920×1080 与 1366×768）检查溢出、断行、图片缺失，产出 `report.md`。

**验收**：见 §9.5。

## 8. Markdown 笔记规范

### 8.1 Frontmatter

```yaml
---
title: 视频标题（可从文件名/内容推断，允许人工改）
source: videos/xxx.mp4
duration: 01:32:45
transcribed_at: 2026-11-11
language: zh
chapters: 8
tags: [标签1, 标签2]
confidence: high | medium | low
---
```

### 8.2 结构

```markdown
# 标题

> 一句话概括本视频解决的问题（≤ 50 字）

## 目录
（带锚点链接）

## 速览（TL;DR）
- 3–6 条，每条 ≤ 30 字，只写结论

## 1. 章节名  `[00:00–12:30]`
### 1.1 小节
正文…
> 💡 要点：一句话
> ⚠️ 注意：易错点/前提条件
> 📌 原话：「引述」 `[05:12]`

（图）![图注](notes.assets/xxx.jpg) `[07:40]`

## 术语表
| 术语 | 解释 | 首次出现 |

## 待确认
- 转写存疑处、需要回看的位置（带时间戳）

## 延伸
- 视频未展开但值得深挖的点（明确标注"视频外补充"）
```

### 8.3 内容规则

- 每个一级章节**必须**带时间范围；每个关键论点**必须**带可点击的 `[mm:ss]`。
- 笔记正文只写视频里有的内容；补充知识写进"延伸"并标注"视频外补充"，不得混入正文冒充原意。
  需要系统展开的内容走 S4.5 的 `enrichment.md`，不要塞进笔记正文。
- 保留原始术语英文（如 `tokenizer`），首次出现给中文解释。
- 公式用 LaTeX，代码用带语言标注的围栏块。
- 不写"本视频介绍了……"这类过程性废话，直接写知识点。
- 长度参考：每 10 分钟视频 ≈ 400–700 字正文；低于 300 字说明提炼过度，高于 900 字说明没提炼。

### 8.4 质量清单（S4 自检项）

- [ ] 时间戳单调递增且不超出视频时长
- [ ] 章节时长的总和 ≥ 视频时长的 95%
- [ ] 所有 `[mm:ss]` 与转写内容能对上（抽查 10 处）
- [ ] 术语表条目都在正文出现过；正文术语都在表里
- [ ] 图片全部存在于 `notes.assets/` 且路径正确
- [ ] `待确认` 段落为空时，删除该段而不是留空标题

### 8.5 知识深挖规范（S4.5）

- 一张卡只说一个知识点，标题是结论而不是名词（"可数性是语法属性"，不是"可数名词"）。
- **原理**必须回答"为什么"，不能把规则换个说法重复一遍；优先讲机制、结构、来源。
- **例**至少给两个，最好形成正误或最小对比（`a university` vs `an hour`）。
- **易错**要具体到学生会写出的错句，不写"容易出错"。
- **迁移**要给下一个动作：换题怎么判断、写句子时检查什么。
- **来源**三选一或组合；`〔扩展〕` 卡片若涉及史实、数据、书目，必须写得出处或明确标"常见说法"。
- 卡片之间允许互相引用（`见 E18`），但不得循环论证。

## 9. HTML 课件规范

### 9.1 技术选型

- **主选 Marp CLI（MIT）**：Markdown → 单文件 HTML，零外链，讲者备注内嵌，可导出 PDF 与逐页 PNG。
  本地实测：109 KB、外链 0、备注 3 处、11 个内联图。
- **备选 reveal.js（MIT，本地 vendored）**：仅当某套课件需要逐页定制版式、目录跳转、深浅色切换时使用。
- 逻辑尺寸 16:9（1280×720），键盘/触控翻页，显示页码与进度条。
- 输出 `slides/index.html`（单文件）+ `slides/theme.css`（中文排版主题）+ 可选 `slides/index.pdf`。

### 9.2 页面类型

| 类型 | 用途 | 规则 |
|---|---|---|
| `title` | 封面 | 标题 + 副标题 + 讲者/日期 |
| `agenda` | 目录 | ≤ 8 项，对应笔记一级章节 |
| `section` | 章节过渡页 | 章节号 + 标题 + 一句话导语 |
| `points` | 要点页 | 3–5 条，每条 ≤ 20 字，可带小图标 |
| `figure` | 图解页 | 大图 + 2–3 条图注，图占 ≥ 60% 面积 |
| `code` | 代码页 | ≤ 12 行，高亮关键行，字号 ≥ 18px |
| `quote` | 引用页 | 原话 + 时间戳 + 出处 |
| `compare` | 对比页 | 两栏/表格，≤ 3 维度 |
| `insight` | 深挖页 | 原理、机制、来源；一个核心问题讲透，不堆要点 |
| `derive` | 迁移页 | 从规则推到新题/新场景，给出判断步骤 |
| `quiz` | 互动页 | 1 个问题 + 展开答案（fragment 控制） |
| `summary` | 小结页 | 3 条回顾 + 下一步 |

### 9.3 密度与排版

- 每页 **≤ 5 个要点**、正文 **≤ 7 行**；超过就拆页——宁多页不挤页。
- 中文正文 ≥ 24px，标题 ≥ 40px，行高 ≥ 1.6；中英文混排留空格（用 `text-spacing` 类或手工）。
- 留白 ≥ 15%；四边安全区 ≥ 48px。
- 页数由信息量决定：45 分钟课 40–60 页正常；单页仍守 ≤5 要点/≤7 行，不靠缩小字号塞内容。
- 每个核心知识点至少一页深挖；深挖页总量建议占全 deck 的 30%–50%。

### 9.4 视觉与交互

- 主题：一套深色 + 一套浅色，通过 `<html data-theme>` 切换，打印默认浅色。
- 颜色全部走 CSS 变量（`:root` 定义），禁止散落硬编码色值。
- 可交互元素：翻页、目录跳转、进度条、讲者备注（`P` 键 presenter 视图）、全屏（`F`）。
- **回看链接（可选）**：每页角落一个时间戳，点击用 `<a href="../../videos/xxx.mp4#t=123">` 打开原视频对应位置
  （依赖浏览器 media fragments，Chrome/Edge 可用；路径可在配置中关闭）。
- 图片一律本地相对路径，禁止外链。

### 9.5 验收

- [ ] 双击 `index.html` 可放映，断网无报错（DevTools 无 404）
- [ ] `file://` 下按 `P` 能打开 presenter 视图，备注可见
- [ ] `index.pdf` 可导出，字体已嵌入，备注在 PDF 中可读
- [ ] 1920×1080、1366×768 下无横向滚动、无文字溢出、无图片拉伸
- [ ] 每页有讲者备注，且备注是口语化的"怎么讲"而非复制要点
- [ ] 每个核心知识点有原理/对比/迁移页，深挖页占比 ≥30%
- [ ] `fact-check.md` 通过门禁：ERROR 已改，CONTESTED 已在页面可见处标注
- [ ] 每页来源角标可见；〔扩展〕页没有冒充讲者观点
- [ ] 页码/总页数正确；目录跳转有效
- [ ] `report.md` 列出：页数、每页字数、疑似过密页、截图路径

## 10. Claude Code 集成方式

| 组件 | 位置 | 职责 |
|---|---|---|
| 技能 | `.claude/skills/video-notes/SKILL.md` | 总流程、产物位置、质量门槛 |
| 技能 | `.claude/skills/outline-grill/SKILL.md` | S3 大纲的设计树追问（grill-me 机制） |
| 命令 | `/video-notes` | 全流程（带 `--from`/`--to` 控制阶段） |
| 命令 | `/video-transcribe` | 只跑 S0–S2，产出转写与帧 |
| 命令 | `/video-notes-write` | 只跑 S3–S4 |
| 命令 | `/video-slides` | 只跑 S5（Marp 渲染） |
| 脚本 | `scripts/*.py` | 确定性音视频处理，单一职责，可独立运行 |
| 门禁 | `scripts/check_outline.py`、`verify_notes.py` | 时间戳覆盖、claim 证据、图片对账，失败阻断下游 |
| 配置 | `config.toml` | 模型、显存精度、抽帧预算、课件引擎与主题 |

触发方式示例：
> "处理 videos/第3讲.mp4，先出笔记给我看大纲"
> "用 notes.md 生成课件，主题用浅色"

**交互原则**：S3 结束必须停下等确认（或显式 `--auto` 跳过），其余步骤失败可重试。

## 11. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 60 分钟视频端到端 ≤ 30 分钟；转写 ≥ 5× 实时（4060 上 large-v3 int8 可达） |
| 成本 | 单视频 Claude 调用控制在 ~150k tokens 内；抽帧预算硬上限 80 帧 |
| 可复现 | 固定随机种子/参数；`meta.json` 记录模型版本与哈希；同输入重跑结果结构一致 |
| 健壮性 | 每阶段幂等；中断后可续跑；异常写明"哪一步、为什么、怎么办" |
| 隐私 | 视频与转写不出本机；只有转写文本与抽帧图会进入 Claude 上下文——需在 README 明示 |
| 磁盘 | 中间产物可 `--clean` 清理；抽帧与音频为临时文件，交付物只保留 output/ |
| 可移植 | 脚本支持 CPU 回退（慢但能跑）；路径含中文/空格可用 |
| 可维护 | 脚本有 `--help`；配置集中；新增页面类型只需加模板 |

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 转写错字（专有名词/口音） | 笔记出现错误概念 | glossary + 低置信度标注 + 人工抽检 |
| 视频无语音（纯演示） | 整条流水线失效 | S0 检测无音轨即停止；提示改用抽帧+视觉理解模式（v1 不做） |
| 长视频超出上下文 | 大纲断裂、遗漏 | 20–30 分钟分块 + 重叠 + 二次合并 |
| 抽帧太多 / 太少 | 成本高 / 漏关键画面 | 帧预算 + 场景分降采样 + 章节邻近取帧 |
| 课件文字溢出 | 放映时难看 | 密度硬规则 + 自动截图检测 |
| 中文排版断行差 | 观感差 | 字号/行高/`word-break` 规则 + 截图人工看 3 页 |
| 版权 | 对外传播风险 | 仅处理自有/授权素材；README 写明责任 |
| Windows 路径问题 | 脚本崩溃 | 统一 `pathlib`，CI 用一条含中文空格的路径测试 |
