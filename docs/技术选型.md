# 技术选型

> v1 ｜ 2026-11-11 ｜ 依据：三路并行调研 + 本地实测（Marp 产物、M0 脚本）
>
> 原则：**只依赖可核实 license 的项目；能借机制就不拷代码；未验证的能力不进主路径。**

---

## 0. 结论

| 层 | 选型 | 理由 | 状态 |
|---|---|---|---|
| 语音转写 | **faster-whisper + large-v3** | 唯一同时满足词级时间戳 / VAD / 热词 / 8GB 显存 | ✅ 采用 |
| 第二意见 | FunASR Paraformer（可选） | 中文标点与热词更强 | 🟡 备选，Windows 未验证 |
| 抽帧 | **自研两段式**：scene + 间隔采样 → dHash 聚类 → 像素复核 → 停留过滤 | 纯 scene 漏渐变页、同一页出多帧 | ✅ 采用 |
| 大纲 | **自建 `outline-grill`**：设计树 + frontier + 推荐答案 + 时间戳证据 | 借鉴 grill-me 机制，不依赖外部仓库 | ✅ 采用 |
| 笔记门禁 | **自研 `verify_notes.py` + 证据表** | 现成项目 license 冲突、平台不符 | ✅ 采用 |
| 课件 | **Marp CLI 为主，reveal.js 备选** | 单文件 / 离线 / 备注 / PDF / 截图全开箱 | ✅ 采用 |
| PPTX | 不引入 ppt-master 代码 | 产出原生 PPTX 而非 HTML，且带署名门禁 | 🔸 只借工作流 |

一句话：**转写用 faster-whisper，抽帧自己写两段式，笔记加证据门禁，课件用 Marp 出单文件 HTML。**

## 1. 调研可信度与冲突处理

| 事项 | 情况 | 处理 |
|---|---|---|
| 直接访问 GitHub | 本机 WebFetch 被域名策略拦截；调研方改用 GitHub REST API + codeload 读源码 | 结论标注"报告方核实"，关键项本地实测 |
| star 数 | 三份报告中的 star 数明显异常且互相不可复核（如 5 万–30 万级） | **不作为任何决策依据，文档不引用** |
| `lecture-to-notes` | 出现两个同名仓库：`drpwchen/`（报告称 MIT、Python 3.12、Windows 8GB）与 `ysyecust/`（报告称 GPL-3.0、含 lecture-to-md skill）；是否同源未核实 | **一律不引入代码**，只借"证据表 + 门禁"机制，clean-room 重写 |
| Marp 单文件 | 本次本地实测：`test.html` 109 KB，外链 0 个，讲者备注 3 处，11 个内联 SVG | 作为主选依据 |
| `ppt-master` | 报告称真实存在、MIT、输出原生 PPTX | 不进主路径 |
| `grill-me` | 报告称在 `mattpocock/skills` 下，MIT，机制为设计树追问 | 不直接安装，自建同机制 skill |

> 结论：**没有一个外部项目可以整体直接依赖**。可复用的是机制与规则，落地代码仍由本仓库掌握。

## 2. 语音转写

### 2.1 候选对比

| 项目 | License | 关键能力 | 适配结论 |
|---|---|---|---|
| **faster-whisper** | MIT | `word_timestamps`、`vad_filter`、`hotwords`、`initial_prompt`、批处理；CUDA 12 + cuDNN 9 | **主力** |
| WhisperX | BSD-2-Clause | 强制对齐、pyannote 说话人分离 | 仅"必须逐字对齐/说话人"时叠加 |
| whisper.cpp | MIT | 单二进制、CPU/GPU、无 Python 依赖 | CPU 兜底，暂不集成 |
| FunASR Paraformer | 代码 MIT / 权重 Apache-2.0 | 中文 CER 强、`fsmn-vad`、`ct-punc`、热词 | 可选第二意见 |
| SenseVoice | 代码 MIT / 权重 Apache-2.0 | 多语种、快；**无原生词级时间戳** | 不做转写主引擎 |
| stable-ts | MIT | — | 已归档，不用 |
| whisper-timestamped | AGPL/GPL 冲突 | — | 许可证不适合，不用 |

### 2.2 决策与参数

```toml
[asr]
model        = "large-v3"       # 追求速度可换 large-v3-turbo
device       = "cuda"
compute_type = "int8_float16"   # 8GB 显存保守值；余量足时 float16
language     = "zh"             # 显式指定，禁止 auto
vad_filter   = true
word_timestamps = true
hotwords     = "<glossary.txt 内容>"
```

- **语言必须显式**：调研方记录了 auto 把带口音英文"幻听"成流利中文的案例，且很难发现。
- **8GB 显存串行**：转写、VLM 读图、抽帧不要并发；默认关闭说话人分离。
- **`hotwords` 与 `prefix` 互斥**：`initial_prompt` 非空时热词可能失效，二选一。
- 需要字符级对齐时再叠 WhisperX；日常 `[mm:ss]` 精度用词级时间戳足够。

### 2.3 术语纠错：标记优先于替换

1. 解码期：`hotwords` 传术语表（成本最低、效果最好）。
2. 后处理：glossary 精确匹配 + 拼音相似度，只替换高置信项，写审计日志。
3. **不跑全量 pycorrector**：它容易把专有名词"纠正"错。调研方实测过两轮自动纠错后废弃，只保留 `asr_suspects.txt` 疑点标记。
4. 简繁统一：转写后把中文文本过一遍 `zhconv`（纯 Python，MIT），只做字符归一化、不改词。
   实测 small 模型默认输出繁体较多，统一后笔记可读性明显提升。

### 2.4 风险

- FunASR 原生 Windows 无官方背书 → 先跑 30 分钟样片再决定是否启用。
- WhisperX 依赖重（torch/pyannote/HF token），默认不装。
- 词级时间戳会漂移，长静音后尤其明显 → 覆盖率检查按段而非按字。

### 2.5 本机实测（2026-11-11）

| 项 | 结果 |
|---|---|
| 环境 | faster-whisper 1.2.1 / ctranslate2 4.9 / Pillow 12.3 / Python 3.10.9 |
| CUDA | 驱动与显卡正常，但缺 `cublas64_12.dll` 与 `cudnn_ops64_9.dll`；PyPI 的 `nvidia-*-cu12` 无 Windows wheel |
| 降级 | `prepare_cuda_dlls()` 检测失败后自动转 CPU/int8，并打印可行动提示；`--device cuda` 会直接报错而不是跑到一半 |
| 吞吐（实测） | tiny CPU int8，90 秒音频 ≈ 7 秒（12.8× 实时）；**large-v3 CPU int8，12:35 视频 20.7 分钟（0.6×）**，265 段，7 段固定幻觉已过滤 |
| 模型下载 | `huggingface_hub` 在镜像下会卡在 0 字节；改用 `scripts/fetch_model.py`（curl + Range 探针 + `-C -` 续传，默认 `hf-mirror.com`） |
| large-v3 必需文件 | 除 `model.bin/config/tokenizer/vocabulary` 外还需 `preprocessor_config.json`（`feature_size=128`）；缺失会报 `(1,128,3000) vs (1,80,3000)` |
| 抽帧 | 6 张幻灯片的合成视频 → 6 帧，时间点 0/15/30/45/60/75 全部正确 |
| ffmpeg 坑 | `fps=1/N` + image2 在 7.1 上出现 PTS 与内容错位；改用 `select='isnan(prev_selected_t)+gte(t-prev_selected_t,N)'` 后正确 |

## 3. 抽帧

### 3.1 为什么不能只用 ffmpeg scene

`select='gt(scene,0.3)'` 只抓硬切：
- 幻灯片淡入、动画、光标移动会漏；
- 同一页在讲解中反复微动会重复出帧；
- 没有"这是同一张幻灯片"的语义。

### 3.2 两段式方案

```
ffmpeg 采样（scene 0.25–0.35 触发 + 每 10–15s 兜底）
        ↓
dHash 64bit 聚类（Hamming ≤ 6 视为同簇）
        ↓
32×32 灰度均值差复核（差异 < 阈值合并）
        ↓
最短停留过滤（< 2s 的翻页动画丢弃）
        ↓
每簇保留最清晰一帧（边缘能量最高）
        ↓
预算裁剪（每 10 分钟 ≤ 12 帧，单视频 ≤ 80 帧）
```

### 3.3 参数

```toml
[frames]
scene_threshold = 0.3
interval_seconds = 12
phash_hamming = 6
min_dwell_seconds = 2
max_frames = 80
max_per_10min = 12
width = 1280
quality = 3
```

### 3.4 依赖

只用 **Pillow**（HPND）做灰度化、缩放、dHash、边缘能量；不引入 OpenCV / scikit-image / imagehash。帧记录：

```json
{"path": "frames/000123.jpg", "t_ms": 123000, "cluster": 7,
 "reason": "scene", "dhash": "…", "sharpness": 142.3}
```

## 4. 大纲与笔记

### 4.1 grill-me 的真实形态（报告方核实）

- 位置：`mattpocock/skills` → `skills/productivity/grill-me/`，底层原语 `grilling`，MIT。
- 机制：把计划建模成 **design tree**，每轮只问 **frontier**（前置决策已定的节点），每个问题附**推荐答案**，用户回答后重算 frontier，直到为空。
- 它**只盘问人，不拿大纲和原文对账**——这是它的能力边界，也是我们必须补的部分。

### 4.2 自建 `outline-grill`（不直接安装）

不依赖外部仓库，按同一机制写自己的 skill：

1. **先跑确定性检查** `scripts/check_outline.py`：
   章节起止单调、无重叠、覆盖率 ≥95%、每章至少 1 个 `[mm:ss]`。
2. **再建决策树**，节点示例：
   - 章节数是否等于视频真实结构？
   - 哪些段落该合并/拆分？
   - 低置信度段落是否需要用户确认？
   - `[图]/[公式]/[代码]` 标记是否齐全？
3. 每轮只问 frontier，每个问题附**推荐答案 + 转写时间戳证据**。
4. 用户只做决策，结果写 `work/<slug>/outline-decisions.md`，S4 以此为约束。
5. frontier 为空时，要求用户确认"大纲已定稿"才进入 S4。

### 4.3 证据表与笔记门禁

从 lecture-to-notes 借机制、**不拷代码**（license 冲突），重写为：

| 文件 | 列 |
|---|---|
| `claims.tsv` | claim / value / source_time / in_notes |
| `atoms.tsv` | atom / status / evidence |
| `figures.tsv` | figure / frame / start / end / topic |

`scripts/verify_notes.py` 门禁项：

- 时间戳单调、不超时长、覆盖率 ≥95%
- 每个数字 claim 在正文出现，且 `source_time` 可回查
- 每个 atom 有 evidence
- 图片存在、manifest 对账、无重复引用
- 术语表与正文一致
- 禁止"根据视频内容"等空话；禁止未标注的自造框架/比喻

末行输出 `OVERALL PASS|FAIL`，失败即阻断进入 S5。

### 4.4 fresh-context reader test

借 `doc-coauthoring` 的流程思想（不复制文本）：让一个**无上下文**的子代理只读 `notes.md`，回答：

1. 这一节讲了什么？
2. 哪里看不懂？
3. 哪个结论没有时间戳支撑？

结果写入 `report.md`。这是发现"作者视角盲区"最便宜的办法。

## 5. 课件

### 5.1 候选对比（针对"离线 + 单文件 + 备注 + PDF + 自检"）

| 项目 | License | 单文件 | 备注 | PDF | 结论 |
|---|---|---|---|---|---|
| **Marp CLI** | MIT | ✅ 本地实测 | ✅ 内嵌 | ✅ `--pdf --pdf-notes` | **主选** |
| reveal.js | MIT | ⚠️ 需自行内联 | ✅ 但官方要求本地服务器 | ✅ `?print-pdf` | 备选 |
| Slidev | MIT | ❌ SPA 目录 | ✅ 依赖 localhost | ✅ | 不用 |
| Quarto | MIT | ✅ `embed-resources` | ✅ | ✅ | 工具链过重 |
| Spectacle / impress.js | MIT | ❌ / ✅ | 弱 | 弱 | 不用 |

### 5.2 决策：Marp 为主

本地实测证据：`npx @marp-team/marp-cli` 在 Windows 11 上把中文 Markdown 渲染为 **109 KB 单文件 HTML**，外链 0，讲者备注内嵌，带 presenter 按钮。
2026-11-11 真实 22 页样例：HTML 348 KB（2 张配图内联后仍无外链），PDF 528 KB / 22 页（含备注），逐页 PNG 1280×720。

```powershell
npx @marp-team/marp-cli output/<slug>/slides.md `
  -o output/<slug>/slides.html --html --theme output/<slug>/theme.css
npx @marp-team/marp-cli output/<slug>/slides.md `
  -o output/<slug>/slides.pdf --pdf --pdf-notes --allow-local-files
npx @marp-team/marp-cli output/<slug>/slides.md `
  --images png -o output/<slug>/selfcheck
```

- 备注：`<!-- 讲者备注：... -->`
- 复杂版式：Markdown 内嵌 `<div>`，需 `--html`
- 逐页截图自检：`--images png` 内置，无需 Playwright

### 5.3 reveal.js 保留场景

仅当某套课件需要**每页不同版式、目录跳转、深浅色切换、时间戳链接**时，用 vendored reveal.js 另出一版。
默认不生成，避免维护两条链路。

### 5.4 ppt-master 结论

- 报告称 `hugohe3/ppt-master`，MIT，输出**原生 DrawingML PPTX**，不是 HTML。
- SKILL.md 内含 `attribution_guard.py` 署名门禁，裁剪/改造会踩门禁。
- **不引入**；只借它的"叙事优先 → 逐页规划 → 图片授权筛选"思路。

### 5.5 中文排版：必须自建主题

没有找到可依赖的中文学术课件主题，自己维护 `theme.css`：

- 字体栈：`"Source Han Sans SC", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif`
- 正文 ≥ 24px，行高 1.6–1.8，标题 ≥ 40px
- 中英混排加间距，标点悬挂，`text-wrap: pretty`
- 深/浅两套，用 CSS 变量切换，打印默认浅色
- 若要求"发给别人排版不变"，子集化中文字体 base64 内嵌（1–3 MB，可选）

### 5.6 自检

- Marp `--images png` 出 1280×720 截图 → 人工/脚本查溢出。
- 溢出检测以 Playwright DOM 测量为准（`scrollWidth > clientWidth`），截图只做兜底。
- 每页字数、要点数、图片存在性、时间戳单调性写进 `report.md`。

### 5.7 风险

- Marp 在 `file://` 下的 presenter 视图未实测（按钮与脚本已内嵌）→ M3 第一件事验证。
- 单文件不内嵌字体，跨机排版可能漂移；PDF 会嵌入字体，分发优先 PDF。
- `npx` 首次安装在 Windows 上较慢 → 可改用 standalone binary 或预热缓存。

## 9. 采纳 / 不采纳清单
